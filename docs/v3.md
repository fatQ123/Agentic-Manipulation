# V3：视觉反馈闭环

当前五模块实现与连续 Demo 见 [模块说明](modules-demo.md)，最终新验收状态见 [进展](progress.md)。旧 V3 的 10/10、异常 3/3 和只抓取结果保留为历史基线，不代替本轮结果。沿用用户现有环境和远程 VLM；服务须支持 JSON 输出模式，非法响应严格拒绝。

## 执行规则

`pick --v3 --instruction ...` 在同一个仿真场景中最多执行三轮，不重置场景。初次解析固定动作、方块颜色和目标容器；恢复时必须用新 RGB-D 重新生成目标框，身份发生变化即停止。

每轮抓取／放置后重新观察，VLM 只收到当前 RGB、原始指令和已确定的语义身份，返回 `status=success|failure|uncertain`、`reason`、`recovery`。失败可选择 `regrasp`、`replace` 或 `stop`；首次无法判断只重新观察、重新定位并再次验证；恢复后仍无法判断则停止，不盲目重复抓取。已夹持的物体仅可重新放置，不会盲目张爪重抓。重新放置的夹持偏移也由最新图像和深度计算，不复用旧目标框。

每任务总时限为 180 秒，Linux 主线程以系统定时器中断超时；网络请求、推理子进程和控制步同时受剩余预算约束。清理录像和仿真资源可能在时限之后完成。非预期碰撞、运动超时、非法响应、HTTP 错误、目标身份变化或不可恢复状态立即终止。V3 每次图文调用仅在连接错误／请求超时时允许再请求一次，仿真保持暂停、重发同一观测，不重复机械动作；两次均失败或总时限耗尽即停止。报告中的 `plan_requests`／`locate_requests`／`verification_requests` 保留请求次数。V1/V2 仍不重试网络调用。

碰撞监测、TCP 标定、桌面间隙和 IK 沿用 V1/V2。夹持传感只用于安全执行；真实物体位姿不用于目标定位、动作生成、恢复、会话状态或 VLM 输入。每轮另用仿真真值连续判分一秒，记录 `truth`；VLM 的输出独立记录在 `verdict`。最终 `success` 以真值为依据，模型判断另见 `agent_status`，两者可能不一致；协议／安全错误导致流程中止时 `success=false`。

## 运行

从项目根目录执行，输出目录必须不存在：

```bash
# 单次闭环任务；也支持“抓起蓝色方块”。
/home/fatbro/software/miniforge3/envs/am-sim/bin/python -m agentic_manipulation.pick --v3 --instruction '把红色方块放进黄色碗里' --seed 0 --output outputs/v3-example --grasp-python /home/fatbro/software/miniforge3/envs/am-grasp/bin/python --checkpoint weights/checkpoint-rs.tar

# 复用 V2 固定十组场景／指令。
/home/fatbro/software/miniforge3/envs/am-sim/bin/python -m agentic_manipulation.evaluate --v3 --output outputs/v3-evaluation --grasp-python /home/fatbro/software/miniforge3/envs/am-grasp/bin/python --checkpoint weights/checkpoint-rs.tar

# 三类真实扰动：首次不闭爪、首次不释放、目标移出工作区。
PYTHONPATH=. /home/fatbro/software/miniforge3/envs/am-sim/bin/python tests/validate_recovery.py --output outputs/v3-recovery --grasp-python /home/fatbro/software/miniforge3/envs/am-grasp/bin/python --checkpoint weights/checkpoint-rs.tar

python3 -m unittest discover -s tests -v
```

省略 `--v3` 保持 V2 单次执行；同时省略 `--instruction` 保持 V1。

## 产物与验收

根目录保存 `pick.mp4`、`result.json`；各 `round-N/` 保存新 `capture/`、`plan.json`、`cloud/`、GraspNet 候选与日志、执行后的 `verification/` 和完成轮次的 `result.json`。重新放置无需重新推理抓取候选。中止时已完成的信息仍保存在根报告，失败目录不会覆盖。

汇总记录每轮 VLM 的误报成功、误报失败和无法判断次数。固定十场景门槛是 `max(9, V2 successes)`；仓库的 V2 基线为 10/10，因此 V3 当前也需要 10/10，并要求物理评测和模型判断都成功。三类扰动另行检查：前两种需要在三轮内恢复成功，目标丢失需要明确停止。十场景通过不代替扰动验收。

历史基线：[十场景完整报告](validation/v3-results.json)、[真实恢复报告](validation/v3-recovery-results.json)、[只抓取报告](validation/v3-pick-results.json)、[恢复演示](validation/v3-demo.mp4)。十场景全部第一轮成功；抓空和未释放在第二轮恢复，目标丢失明确终止。模型为 `qwen3.8-flash`，正常整批的服务与模型在启动时固定；同 V2 的环境版本可见采集元数据及既有包清单。

旧版本最终十场景、三类异常与只抓取共 16 次有效 VLM 判断，均与独立真值一致。该结果仅覆盖这些固定样本。此前 6/10、9/10、异常 2/3 和只抓取误判的完整失败记录均保留，详见 [测试记录](tests.md)；预设反馈诊断不计入真实验收。最终正常整批没有触发通信重试，通信重试边界由离线测试覆盖。

限制：固定颜色方块、固定容器几何与单视角；未知／遮挡状态宁可停止。依赖远程 VLM 的可用性与判断质量，不保证任意物体、复杂障碍物或实机可靠性。
